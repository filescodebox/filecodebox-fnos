### manifest `desc`(= 应用中心「应用介绍」)编写规则

应用介绍直接取 fpk 内 manifest `desc`,前端经 filterXSS 白名单渲染为 HTML(允许 `<strong>`/`<br>`/`<p>`/`<ul>`/`<a>`/`<img>`,`class`/`style` 属性被丢弃;正文换行会转成 `<br/>`,展示最多 8 行后折叠展开)。fnpack 的 manifest 是 INI 风格,写入有三个硬约束(2026-10-13 实测):

- **`;` 与 `#` 会被当注释砍掉**:`desc=前半句;后半句` 打包后 desc 只剩前半句,余下成为独立注释行——线上介绍曾长期只剩半句就是这个原因;
- **不能换行**:第二行起会被解析成新的 key(同理,多条 `changelog=` 只有**最后一条**存活);
- 所以长介绍必须写成**单行 HTML**: `desc=<strong>…</strong>…。<br/>…。`(回环验证:HTML 标签、`:`、`《》`、`、` 均原样保留)。

截图若需更新:重跑 docs-site 截图流水线(hub 仓,2026-10-08 已对齐新 UI),再跑本脚本;`SHOTS_DIR` 可指向其他目录。

## 三、发布前测试基线(官方要求)

官方要求在「计划支持的 fnOS 版本和硬件架构」实测后才可声明支持范围。已覆盖:

- fnOS 1.2.0701 x86_64 真机:全新安装/桌面入口/启停/应用内升级/卸载重装/看门狗自愈全绿(见 fnos v1.2.7+ 真机回归记录);v1.14.6 深度融合(SSO 免登录真会话/统一网关防伪造/授权目录)真机验证收官。
- **缺口**:aarch64 真机未实测(包内有双架构静态二进制,但仅 CI 冒烟)——提交前如实向工作人员说明,或找 ARM 设备补测。

## 五、上架后持续运营

- **每列车同步**:train 发版 → CI 产出 fpk 挂 hub Release → 重跑 `assemble-store-package.sh` → 群内提交新版(与 iStore PR 同节奏)。manifest `changelog` 即版本说明,确保每列车已更新。
- **官方审核退回**:按群内反馈修;审核周期未知,首版按 1-2 周预期。
- **紧急修复**:P0 热修列车发版后,主动在群内说明修复内容加速审核(参考 iStore 渠道经验)。

## 六、审核关注点预备(内容安全类应用)

匿名分享类应用审核大概率关注内容合规,已有应对:

| 可能问询 | 事实依据(如实陈述) |
|---|---|
| 匿名滥用/违法内容 | 页脚合规声明(网络安全法);moderation 域内置敏感词审核钩子(可配 ClamAV) |
| 账号滥用 | 默认关闭开放注册(管理员建号);生产模式库中无 admin 且未注入密码拒绝启动 |
| 数据安全 | 数据全落用户自有 NAS 共享目录;支持取件密码与端到端加密分享;到期自动销毁 |
| 端口/暴露面 | 单进程单端口(默认 12345);管理面可独立门禁;不收集外部数据(全开源可审计) |
